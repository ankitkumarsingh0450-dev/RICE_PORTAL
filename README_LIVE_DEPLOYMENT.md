# RICE PORTAL – Updated Version

This package implements the changes from the supplied Excel requirement.

## What is included

- Home dashboard with SO Month-wise SO Value / Billed Value / Pending Value.
- Fill Rate on Home: Vendor-wise, Product Brick-wise and Overall, using SO Month.
- Purchase Report: SO Month-wise, Crop Type-wise, Purchase Qty in EA from Rice Data.
- Del % Report: SO Month-wise, Crop Type-wise, Delivered Quantity from RICE DATA (`BILLED QUNTITY`).
- Top Performance: SO Month-wise Vendor / Article / Customer with SO Value and Billed Value.
- Sauda: one form, multiple articles, save/edit/delete and Sauda Data.
- Vendor Invoice Tracking: ONE PAGE containing all 4 stages; multiple SOs/articles; VITR number; edit/delete; PDFs; Pending/finished status.
- CSV Upload page with four independent templates and header validation:
  - RICE DATA
  - BILLED DATA
  - SALES DATA
  - RSO/RTV/INV.CANCELLED DATA
- Rice upload uses SO No + Article Code as the unique key and overwrites an existing row instead of creating a duplicate.

## Important before running

1. Copy `backend/.env.example` to `backend/.env`.
2. Run `database/schema.sql` for a fresh database.
3. If you already have the old `rice_portal` database, run `database/migration_2026_09.sql` once.
4. Install dependencies in `backend` and `frontend` with `npm install`.
5. Start backend with `npm start` and frontend with `npm run dev`.
6. Local login: `admin` / `admin123`.

## Free online architecture

Recommended:

Browser → Render Static Site (React) → Render Web Service (Node/Express) → TiDB Cloud Starter (MySQL-compatible)
                                                     └→ Cloudinary (PDF storage)

Why these services:
- Render provides free static sites and free web services. Free web services sleep after 15 minutes of inactivity and their local filesystem is ephemeral.
- TiDB Cloud Starter is MySQL-compatible and currently provides a free quota (within limits) without a credit card.
- Cloudinary can keep Vendor Invoice PDFs outside Render's temporary filesystem.

## Render settings

### Backend Web Service

- Name: `rice-portal-api`
- Root Directory: `backend`
- Build Command: `npm install`
- Start Command: `npm start`
- Plan: Free
- Health Check Path: `/api/health`

Environment variables:

```
DB_HOST=<TiDB public host>
DB_PORT=4000
DB_USER=<TiDB prefix>.root
DB_PASSWORD=<TiDB password>
DB_NAME=rice_portal
DB_SSL=true
DB_SSL_REJECT_UNAUTHORIZED=false
JWT_SECRET=<long-random-secret>
CLOUDINARY_CLOUD_NAME=<cloud-name>
CLOUDINARY_UPLOAD_PRESET=<unsigned-upload-preset>
```

### Frontend Static Site

- Name: `rice-portal-web`
- Root Directory: `frontend`
- Build Command: `npm install && npm run build`
- Publish Directory: `dist`

Environment variable:

```
VITE_API_URL=https://rice-portal-api.onrender.com
```

Use the exact API URL generated by your Render backend.

## TiDB setup

Create a TiDB Cloud Starter instance, open **Connect**, use the public connection details, create a password, and then run `database/schema.sql` in the TiDB SQL Editor. TiDB uses the MySQL protocol, so the existing Node `mysql2` code can connect to it.

For an existing database, run `database/migration_2026_09.sql` instead of recreating all tables.

## Cloudinary PDF setup

Create a free Cloudinary account and create an unsigned upload preset. Put the cloud name and preset name into Render environment variables. The portal accepts PDFs up to 10 MB for Vendor Invoice / RCPL Invoice / POD.

If Cloudinary variables are not configured, local development stores files under `backend/uploads/`. Do not rely on that storage for Render production because Render's free filesystem is temporary.
